== FITLYTICS WORKOUT — NOTATKI PROJEKTU ==

--- CO ZOSTALO ZROBIONE ---

[STRUKTURA]
- fitlytics-workout/ (root repo)
- backend/ — FastAPI + SQLAlchemy + MySQL
- frontend/ — placeholder (.gitkeep), docelowo Vue/Vite (port 5173)
- .gitignore w root (pokrywa caly projekt)

[BACKEND — PLIKI BAZOWE]
- database.py      — polaczenie MySQL przez SQLAlchemy 2.0, Base (DeclarativeBase), SessionLocal, get_db()
- main.py          — FastAPI app, CORS (localhost:5173), endpoint GET /, wszystkie routery podpiete
- requirements.txt — przypiety stack (FastAPI, SQLAlchemy, pymysql, passlib, bcrypt, jose, pydantic)
- .env / .env.example
- seed.py          — wypelnia baze: 9 partii miesniowych, 21 cwiczen z ExerciseMuscle (is_primary)

[MODELE — models/models.py]
- User            — id, email, username, hashed_password, created_at
- MuscleGroup     — id, name
- Exercise        — id, name, category, equipment, description
- ExerciseMuscle  — tabela laczaca (exercise_id, muscle_group_id, is_primary)
- WorkoutSession  — id, user_id, date, duration_minutes, notes, planned_end
- WorkoutSet      — id, workout_session_id, exercise_id, weight_kg, reps, set_number, duration_seconds, distance_km, created_at
- WorkoutPlan      — id, user_id, name, description, planned_date, deadline, is_completed, created_at
Relacje: User->WorkoutSession->WorkoutSet, User->WorkoutPlan, Exercise->WorkoutSet, Exercise->ExerciseMuscle, MuscleGroup->ExerciseMuscle

[AUTH — core/]
- core/security.py — hash_password, verify_password, create_access_token, decode_token (JWT via python-jose)
- core/deps.py     — get_current_user (OAuth2PasswordBearer, tokenUrl=/auth/login)

[SCHEMATY — schemas/]
- schemas/user.py     — UserCreate, UserLogin, UserOut (Pydantic v2)
- schemas/exercise.py — MuscleGroupOut, ExerciseCreate, ExerciseOut
- schemas/session.py  — SessionCreate, SessionEnd, WorkoutSetOut, SessionOut, SessionDetailOut

[ROUTES — routes/]
- routes/auth.py
    POST /auth/register (201, UserOut)
    POST /auth/login (zwraca access_token + token_type)

- routes/exercises.py
    GET  /exercises?muscle_group= — lista cwiczen, opcjonalny filtr po partii
    GET  /exercises/{id}          — detal cwiczenia
    POST /exercises               — dodaj cwiczenie (201)
    DELETE /exercises/{id}        — usun cwiczenie
    ExerciseOut zawiera primary_muscles i secondary_muscles (lista MuscleGroupOut)

- routes/sessions.py
    POST  /sessions               — nowa sesja (201, SessionOut)
    PATCH /sessions/{id}/end      — zakoncz sesje, zapisz duration_minutes
    GET   /sessions               — ostatnie 20 sesji usera (najnowsze pierwsze)
    GET   /sessions/{id}          — detal sesji z lista setow (SessionDetailOut)
    403 jesli sesja nie nalezy do usera

- routes/sets.py
    POST   /sets                        — zaloguj set (201, SetOut); 403 jesli sesja nie nalezy do usera; 404 jesli cwiczenie nie istnieje
    GET    /sets/session/{session_id}   — sety z danej sesji (posortowane po exercise_id, set_number); 403 jesli nie twoja sesja
    DELETE /sets/{set_id}               — usun set; 404 jesli nie istnieje; 403 jesli nie twoja sesja

- schemas/set.py
    SetCreate — walidacja: set_number > 0, przynajmniej weight_kg lub duration_seconds wymagane (@model_validator)
    SetOut    — id, workout_session_id, exercise_id, weight_kg, reps, set_number, duration_seconds, distance_km, created_at

- routes/progress.py
    GET /progress/{exercise_id}     — historia progresji dla cwiczenia (query: days=90); max_weight, total_volume, best_set_reps per sesja
    GET /progress/records           — rekordy zyciowe usera per cwiczenie (max weight_kg + data osiagniecia); pomija cardio (null weight)
    GET /progress/weekly-volume     — objetosc treningowa per tydzien (query: weeks=12) z rozbiciem na partie miesniowe (MuscleVolumeBreakdown)
    GET /progress/monthly-days      — dni treningowe w miesiacu (query: year, month); zwraca liczbe i liste dat

- schemas/progress.py
    ProgressPoint, PersonalRecord, MuscleVolumeBreakdown, WeeklyVolume, MonthlyTrainingDays

- routes/plans.py
    POST   /plans                  — nowy plan (201, PlanOut)
    GET    /plans?include_completed=false — lista planow usera posortowana po planned_date asc
    PATCH  /plans/{plan_id}        — aktualizuj plan (planned_date, deadline, is_completed); 403/404
    DELETE /plans/{plan_id}        — usun plan; 403/404; zwraca {"message": "Usunięto"}

- schemas/plan.py
    PlanCreate — name, description, planned_date, deadline; walidacja: deadline > planned_date (@model_validator)
    PlanUpdate — planned_date?, deadline?, is_completed? (wszystkie opcjonalne)
    PlanOut    — id, name, description, planned_date, deadline, is_completed, created_at, is_overdue (wyliczane w runtime)

UWAGA: kolejnosc endpointow w progress.py — /records, /weekly-volume, /monthly-days przed /{exercise_id} (FastAPI dopasowuje po kolejnosci)
